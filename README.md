# Eureka-microservice (eureka-server)

[![Java Version](https://shields.io)](https://oracle.com)
[![Spring Boot](https://shields.io)](https://spring.io)
[![Spring Cloud](https://shields.io)](https://spring.io)

Центральный сервер обнаружения и регистрации сервисов (Service Discovery) всей распределенной системы на базе **Netflix Eureka Server**. Микросервис выполняет роль динамической «регистратуры» архитектуры: он аккумулирует IP-адреса и порты всех запущенных инстансов и предоставляет актуальный реестр сетевых узлов для API Gateway и gRPC-клиентов.

## 🛠️ Стек технологий и особенности

* **Синхронизация инфраструктуры (Java 21 + Spring Boot 3.4.2):** Проект переведен на стек Java 21 и Spring Cloud 2024.0.0. Это гарантирует 100% совместимость структуры сериализации метаданных при приеме Heartbeats (пульса) от СУБД-микросервисов и игрового движка нового поколения.
* **Сжатие оверхеда (Project Loom):** Включена нативная поддержка виртуальных потоков Java 21 (`spring.threads.virtual.enabled=true`). Внутренние планировщики и таймеры Эврики (`eviction-timer`, `renewExecutor`) полностью переведены на легковесные потоки Loom, разгружая операционную систему от фонового удержания тяжелых ОС-потоков.
* **Изолированный запуск:** С помощью конфигурации `spring.autoconfigure.exclude` из контекста принудительно удалены автоконфигурации `DataSourceAutoConfiguration` и `HibernateJpaAutoConfiguration`. Сервер запускается в ультра-легковесном режиме без ложного поиска реляционных баз данных.

## ⚡ Оптимизация под Highload (Агрессивные таймауты)

В стандартных конфигурациях Netflix Eureka считает упавший сервис «живым» до 90 секунд, что недопустимо при активном игровом процессе Тетриса. В данном микросервисе применены агрессивные настройки вычищения реестра:

* **Моментальная реакция (Eviction Interval):** Интервал сканирования и очистки неживых узлов уменьшен до **5 секунд** (`eureka.server.eviction-interval-timer-in-ms=5000`) вместо стандартных 60 секунд.
* **Отключение Self-Preservation:** Режим самосохранения принудительно деактивирован (`eureka.server.enable-self-preservation=false`). В условиях локального контура и Pet-проектов это гарантирует, что мертвые или аварийно завершенные инстансы Тетриса будут мгновенно удаляться из таблицы маршрутизации, избавляя API Gateway от ошибок `503 Service Unavailable`.
* **Автономный Standalone-режим:** Параметры `registerWithEureka=false` и `fetchRegistry=false` корректно изолируют инстанс, запрещая серверу регистрироваться в самом себе и плодить бесконечные циклические запросы.

## 🚀 Запуск проекта

### Требования
* Установленный JDK 21
* Установленный Maven 3.9+

### Порядок запуска
1. Перейти в каталог проекта `Eureka-microservice`.
2. Скомпилировать и очистить проект: `mvn clean compile`.
3. Запустить класс `EurekaServer`. Сервер развернет дашборд и начнет слушать входящие запросы на порту **1111**. Панель управления доступна в браузере по адресу: `http://localhost:1111`.
